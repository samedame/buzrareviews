## Phase 3

6. **Added `.claude/**`, `.agents/**`, `qa-artifacts/**`, and `docs/design/references/**` to `eslint.config.mjs`'s `globalIgnores`.** The H1 scoped lint command was specified before Phase 0 installed any plugins/skills; without this, ESLint walks into vendored third-party scripts (e.g. `.claude/skills/impeccable/scripts/live-browser.js`, a minified-looking bundled file) and produces ~94 bogus warnings that have nothing to do with our source. This mirrors `.gitignore`'s existing exclusions for the same directories, so the scoped lint gate now only ever reports on our own code. Verified `npx eslint . --ignore-pattern ... ` is back to 0 problems and `npm run lint` shows exactly the 5 known pre-existing errors.
7. **Loaded `Libre_Franklin` and `Atkinson_Hyperlegible_Next` with `weight: "variable"` instead of an array of static weights.** Both support a `variable` weight option in this Next.js version's font data (confirmed in `node_modules/next/dist/compiled/@next/font/dist/google/font-data.json` and the type declarations) which loads the true variable font file, matching DESIGN.md's "variable font" requirement and letting CSS set any weight in range rather than only the three named ones.
8. **Built a separate `LogoMark` component instead of reusing `Stars` with `max=1` for the single-star logo.** `Stars` always sets `role="img"` with an `aria-label` like "1 out of 1 stars," which is semantically wrong for a decorative logo mark (there's no rating being conveyed). `LogoMark` renders the same star path `aria-hidden`, letting the adjacent wordmark text carry the link's accessible name.
9. **Never pass a `hidden`/responsive-display class directly into `Button`'s `className` prop; wrap it in a container div instead.** Caught via screenshot: `Button`'s own `base` classes unconditionally include `inline-flex`, and Tailwind's generated CSS does not reliably let a `className`-prop utility (`hidden sm:inline-flex`) win over a component's own baked-in display utility at the same specificity — cascade order depends on Tailwind's generation order, not the order classes appear in the class attribute. Fixed the header's desktop-only "Start free trial" button by wrapping it in `<div className="hidden sm:block">` instead. Applies to any future Button usage that needs to be conditionally hidden.

## Phase 4

10. **Removed `color: var(--color-ink-2)` from the `.text-lead` custom CSS class instead of letting call sites override it with a `text-ink-on-dark` Tailwind utility.** Same underlying issue as #9: a color baked into a hand-written CSS class and a same-specificity Tailwind color utility applied at the call site can lose the cascade in either direction depending on Tailwind's generation order, not source order in the class attribute. Rather than hit this bug a second time on the dark final-CTA band (which needs `.text-lead`'s sizing but `ink-on-dark`'s color instead of the default `ink-2`), made `.text-lead` color-agnostic and require every call site to pass an explicit `text-*` color utility. Same reasoning applies to any future shared typography class that multiple differently-colored sections reuse.
11. **Added `switchLabelShort` to each `VerticalDemo` and show it only below the `sm` breakpoint.** Caught via mobile screenshot: "Salon / Dental office / Restaurant" plus the "Example" tag didn't fit on one row at 390px and wrapped awkwardly. DESIGN.md's own spec already calls for "short labels on mobile" for the vertical switch; added the data field it was missing.
12. **Suppressed `react-hooks/set-state-in-effect` once in `useReviewLoopSequence.ts`, with a comment, rather than restructuring the hook.** The effect's job is to synchronize component state with an external timer-driven system (the choreography's `setTimeout` chain) in response to `runToken`/`mode`/`rating` changes -- exactly the exception React's own docs carve out for this lint rule ("subscribe for updates from some external system"). There's no derived-state anti-pattern to fix here; rewriting it to dodge the rule's pattern-matcher (e.g. wrapping a plain value in a no-op function) would be cosmetic, not a real fix. Verified this is the only occurrence and the scoped lint gate is otherwise clean.

## Phase 5

13. **`ContactForm`'s anti-spam timestamp uses `useState(() => Date.now())`, not `useRef(Date.now())`.** `useRef`'s initial-value argument is still evaluated on every render even though only the first call sticks, so ESLint's `react-hooks/purity` rule correctly flags a bare `Date.now()` there as an impure call during render. `useState`'s lazy initializer form is the React-blessed way to capture an impure value exactly once at mount.
14. **Added a `mainStreetPhoto` field to `src/config/site.ts`**, matching `founderPhoto`'s `null`-by-default, `// TODO(Sam)` pattern. F1's original site-config field list didn't include it, but F5 explicitly calls for a Main Street photo slot on `/bozeman` that renders only when configured, so a config field had to exist somewhere; extending the existing pattern was the smallest consistent choice.
15. **Deleted the stock `create-next-app` `favicon.ico`** rather than leaving it alongside the new `icon.svg`/`apple-icon.tsx`. Some browsers request `/favicon.ico` directly regardless of `<link rel="icon">` tags, and the leftover default (off-brand, generic Next.js logo) would have shown the wrong tab icon in those cases. `icon.svg` (modern browsers) and `apple-icon.tsx` (iOS home screen) now cover the favicon requirement on their own.
16. **Downloaded a static Libre Franklin ExtraBold TTF for `opengraph-image.tsx`** via the Google Fonts CSS2 API with a legacy user agent (per MASTER_PROMPT.md F7's own instruction) rather than trying to use the variable font already loaded via `next/font` -- `ImageResponse` (Satori) cannot render variable or WOFF2 fonts, only static TTF/OTF. Committed under `src/app/fonts/`, SIL Open Font License.
